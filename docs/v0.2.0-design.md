# v0.2.0 Design

Status: planned.

Theme: cleaner command model, durable reasoning, and traceable thought provenance.

## Architecture Direction

v0.2.0 should strengthen NuSelf as a multi-subservice system.

Memory, reflection, notification, trace, and reason should each have clear module boundaries:

- domain models;
- file-backed repository;
- service interface;
- renderer;
- tool-facing adapter for other agents.

This creates a complex but legible service network. Chat, reflection, reason, and future agents should call service/tool interfaces rather than directly manipulating another subsystem's files.

## Release Goal

v0.2.0 should make NuSelf feel less like a bundle of internal subsystems and more like a stable personal thinking tool.

The release has three pillars:

1. **Command cleanup**: reorganize the CLI and REPL around user-facing concepts.
2. **Reason**: add durable long-run reasoning threads for explicit questions.
3. **Trace**: add a thought provenance database so important thoughts can be traced after chats are compressed and memories are curated.

This is a breaking release. The new command model should replace old command paths directly; do not keep compatibility aliases unless a specific safety issue appears during implementation.

## Pillar 1: Command Cleanup

Top-level commands should be small and conceptual:

```text
nuself                 # open interactive chat
nuself chat            # explicit chat
nuself daemon          # background process
nuself thread          # conversation threads
nuself memory          # memory, sources, profile, review, graph
nuself inbox           # reflection, notification, reason updates
nuself reason          # long-run reasoning threads
nuself trace           # thought provenance records
nuself dev             # logs, health, config, eval, diagnostics
```

Remove old top-level command paths in this release:

| Old | New |
|---|---|
| `nuself source ...` | `nuself memory source ...` |
| `nuself reflection ...` | `nuself inbox reflection ...` |
| `nuself notify ...` | `nuself inbox notify ...` |
| `nuself logs ...` | `nuself dev logs ...` |
| `nuself status` | `nuself dev status` or `nuself daemon status` |
| `nuself health` | `nuself dev health` |
| `nuself config` | `nuself dev config` |
| `nuself eval` | `nuself dev eval` |
| `nuself memory candidate ...` | `nuself memory review ...` |
| `nuself thread create ...` | `nuself thread new ...` |

Top-level help should be grouped by use:

```text
Daily:
  nuself
  nuself chat
  nuself attach

Objects:
  thread
  memory
  inbox
  reason
  trace

System:
  daemon
  dev
```

REPL commands should mirror the same concepts:

```text
:inbox
:i
:mem
:m
:thread
:t
:reason
:trace
:dev
:export
:e
:q
```

## Pillar 2: Reason

Reason is the long-run reasoning subsystem. It maintains a small set of explicit user-approved questions and advances them over time.

v0.2.0 scope:

- `ReasoningThread` and `ReasoningStep` domain models.
- File-backed repositories under `private/reasoning/`.
- Manual CLI and REPL commands: `list`, `show`, `start`, `advance`, `pause`, `resume`, `resolve`, and `archive`.
- Manual `advance` only. No background scheduler yet.
- Chat can read active reason summaries when relevant.
- Chat must not silently create a reason thread.
- Reflection promotion into reason: `nuself inbox reflection promote <id_or_index>`.

Reason steps should write trace records.

## Pillar 3: Trace

Trace is the thought provenance system.

It records how NuSelf arrived at an important answer, memory, reflection, reason step, or decision. Trace is not raw model chain-of-thought. It is a system-level provenance record containing inputs, evidence, participant agents, decision points, outputs, and links to derived artifacts.

v0.2.0 scope:

- `ThoughtTrace` domain model.
- `TraceLink` relation model.
- File-backed `TraceRepository` under `private/traces/`.
- CLI and REPL commands: `list`, `show`, and `search`.
- Record traces for reason thread creation, reason advance, reflection promotion into reason, and important chat answers when the agent used memory, source, reflection, or reason context.

Trace graph visualization can wait until a later release.

## Implementation Order

1. Write/update specs: CLI, trace, long reasoning, and chat-agent tools.
2. Implement command cleanup parser structure and tests.
3. Implement trace domain/repository/rendering.
4. Implement reason domain/repository/rendering.
5. Add reason advance and trace recording.
6. Add reflection promotion into reason and trace.
7. Add chat read-only reason/trace awareness.
8. Update README, changelog, and version planning.

## Non-Goals

- Do not keep old command compatibility aliases.
- Do not add scheduled reason advancement yet.
- Do not add reason notifications yet.
- Do not record raw hidden model chain-of-thought.
- Do not build trace graph visualization yet.
- Do not replace memory curation with trace.

## Completion Criteria

- New CLI tree is implemented and documented.
- Old top-level command paths are removed.
- Reason threads can be manually created, shown, advanced, paused, resumed, resolved, and archived.
- Trace records can be listed, shown, and searched.
- Reason steps and reflection promotion create trace records.
- Chat can reference active reason summaries without silently creating reason threads.
- README, specs, and CHANGELOG are updated.
- `uv run pytest`, `uvx pyright`, and `git diff --check` pass.
